# Found for Less · India Price Desk

An India-first, Azure-targeted affiliate product discovery and price-comparison tracker. The current implementation is a functional preview with INR prices, Flipkart/Myntra/Ajio retailer filters, category search, sorting, saved products, transparent offer timestamps, structured click/search events, and an allowlisted affiliate redirect route.

The product name is provisional. Product details, prices, merchant destinations, and images in the preview catalog are demonstration data and MUST NOT be presented as live merchant data.

## Run locally

Requirements: Node.js 22 and npm.

```powershell
Copy-Item .env.example .env.local
npm install
npm run dev
```

Open [http://localhost:3000](http://localhost:3000). Run the full local verification with:

```powershell
npm run check
```

## Turn on affiliate links

The checked-in catalog uses ordinary merchant search URLs and does not earn commissions. To monetize an offer:

1. Obtain written approval from the merchant or affiliate network.
2. Generate the program's permitted deep link for the exact product or search destination.
3. Confirm whether the program permits an intermediate redirect and custom sub-ID. Some programs require direct links.
4. Add the URL to local `.env.local` using `AFFILIATE_URL_<OFFER_ID>`, where hyphens become underscores and letters are uppercase.
5. In Azure, store each configured URL in Key Vault and expose it to Container Apps as a secret-backed environment variable.
6. Click the offer and verify the network dashboard records the click before publishing it.

Example:

```dotenv
AFFILIATE_URL_OFFER_REV7_FLIPKART=https://www.flipkart.com/search?q=Nike%20Revolution%207&YOUR_APPROVED_NETWORK_PARAMETERS
```

Do not guess the parameter name shown conceptually above. Replace the entire value with the exact deep link generated by the approved network. The checked-in value in `.env.example` intentionally remains a non-commission merchant URL.

The route `/go/[offerId]` generates a click ID, replaces `{{click_id}}` where the network supports a sub-ID, writes a structured `affiliate_click` event, validates HTTPS and the merchant domain, and returns a non-cacheable `302`. It never accepts a destination URL from the browser, which prevents an open redirect.

See [Affiliate and search monetization](docs/AFFILIATE_AND_SEARCH_MONETIZATION.md) before adding a real network.

## Search analytics

Search text, category, and retailer filters are debounced in the browser and POSTed to `/api/events/search`. The route limits and sanitizes input, records `catalog_search` as structured JSON, and returns `202`. Application code does not attach an IP address, account ID, advertising ID, or cookie ID. Azure infrastructure can still produce access logs, so retention, access, and Indian privacy requirements must be configured before launch.

Useful business joins after PostgreSQL and Service Bus are connected:

- Search query to result count and zero-result rate.
- Search query to outbound click-through rate.
- Click ID to network conversion and commission import.
- Merchant, placement, and campaign to EPC (earnings per click).
- Category demand to missing merchant or catalog coverage.

## Azure target

The production target is Azure Container Apps with managed ingress, a custom domain and managed TLS. The app is packaged with Next.js standalone output in [Dockerfile](Dockerfile). The planned data tier is PostgreSQL Flexible Server, Blob Storage, Service Bus, and Azure AI Search, with Key Vault, App Configuration, Azure Monitor, Application Insights, and Log Analytics for operations. Azure Front Door with WAF is deliberately not used at launch and is revisited only if bot abuse or multi-region routing is evidenced.

Do not set `NEXT_PUBLIC_SITE_MODE=production` until approved feeds, truthful structured data, policy pages, consent behavior, merchant link checks, and launch acceptance tests are complete. Preview mode emits `noindex, nofollow` metadata.

Detailed architecture, scope, risks, epics, and launch gates are in the [product and Azure implementation plan](docs/projects/feature-affiliate-marketplace/feature-affiliate-marketplace.prd.md).

## Deploy to Azure

Deploy to **your own** Azure subscription, not a shared or employer subscription — this site earns affiliate commission and is a personal commercial workload.

```powershell
az login
az account set --subscription "<your-subscription-id>"
az deployment sub create `
  --location centralindia `
  --template-file infra/main.bicep `
  --parameters infra/main.bicepparam
```

That creates a resource group with a Container Apps environment, the app, a Basic container registry, Key Vault, Log Analytics and Application Insights, plus a user-assigned identity holding `AcrPull` and `Key Vault Secrets User`. The registry has admin credentials disabled; image pulls use the managed identity.

The first deployment runs the Azure quickstart image so it succeeds before any image exists. Push the real one and re-deploy with the tag:

```powershell
az acr build --registry <registryName> --image web:v1 --file Dockerfile .
az deployment sub create `
  --location centralindia `
  --template-file infra/main.bicep `
  --parameters infra/main.bicepparam `
  --parameters containerImage="<registryLoginServer>/web:v1"
```

[.github/workflows/deploy.yml](.github/workflows/deploy.yml) does this automatically on push to `main` using OIDC — no stored credentials. It needs `AZURE_CLIENT_ID`, `AZURE_TENANT_ID` and `AZURE_SUBSCRIPTION_ID` as repository secrets, and a federated credential on the app registration.

Set `minReplicas` to `0` in [infra/main.bicepparam](infra/main.bicepparam) to scale to zero and cut idle cost, at the price of cold starts.

### Custom domain

```powershell
az containerapp hostname add --name <containerAppName> --resource-group <rg> --hostname www.example.in
az containerapp ssl upload --help   # or use a free managed certificate
```

Your DNS needs a `CNAME` to the app's default FQDN and a `TXT` record named `asuid.<subdomain>` holding the app's verification ID. Once the domain resolves, set `siteUrl` in the parameters file and switch `siteMode` to `production` — that flips `robots.txt` and page metadata from `noindex` to indexable.
